# nixos-config

Flake-based NixOS configuration, migrated from a single monolithic
`/etc/nixos/configuration.nix`.

## Layout

```
flake.nix                     inputs (nixpkgs, musnix) and the nixosConfigurations output
hosts/
  t480s/
    default.nix                this machine's entrypoint: imports modules + hardware scan
    hardware-configuration.nix  generated by nixos-generate-config, left untouched
modules/
  boot.nix                     bootloader
  locale.nix                   timezone, locale, console keymap
  networking.nix                NetworkManager, avahi (mDNS/network discovery)
  desktop.nix                   X11, GDM, GNOME, fonts, keyboard layout
  audio-bluetooth.nix           pipewire/pulseaudio, bluetooth, gamepad driver
  printing.nix                  CUPS
  shell.nix                     zsh, tmux, direnv
  gaming.nix                    Steam, ratbagd
  virtualisation.nix            Docker
  containerlab.nix              containerlab + setuid wrappers + clab_admins group
  users.nix                     the `joel` user and their packages
  packages.nix                  general system packages, flatpak, allowUnfree
  nix-settings.nix              nix.settings, gc, autoUpgrade, stateVersion
```

Each module is a self-contained slice of the old configuration.nix, grouped by
subsystem rather than by chronology. Nothing in `modules/` is host-specific;
host-only facts (hostname, hardware scan) live under `hosts/t480s/`.

## Adding a second host

1. `mkdir hosts/<name>`, copy a fresh `hardware-configuration.nix` into it.
2. Write `hosts/<name>/default.nix` importing whichever `modules/*.nix` apply,
   plus any host-only options.
3. Add `nixosConfigurations.<name> = nixpkgs.lib.nixosSystem { modules = [ musnix.nixosModules.musnix ./hosts/<name> ]; };`
   to `flake.nix`.

## Rebuilding

From the repo (works regardless of the `/etc/nixos` symlink):

```
cd ~/nixos-config
sudo nixos-rebuild switch --flake .#t480s
```

Or, since `/etc/nixos` is a symlink to this repo, the plain form also works:

```
sudo nixos-rebuild switch
```

Always `git add` new files before rebuilding — flakes only see files known to
git (tracked or staged), so an untracked new module silently won't be picked up.

## Updating packages

`nixpkgs` is pinned in `flake.lock`, matching the channel (`nixos-26.05`) the
machine was already running when this repo was created — so the initial
switch to flakes was a no-op. To pull newer packages later:

```
nix flake update
sudo nixos-rebuild switch --flake .#t480s
```

Commit the updated `flake.lock` once you're happy with the result.

## autoUpgrade note

The original config's `system.autoUpgrade.channel` pointed at a channel URL
and fetched/rebuilt from it nightly. Flakes don't upgrade that way: autoUpgrade
is now set to `flake = "/home/joel/nixos-config#t480s"`, which rebuilds from
this local checkout's **currently committed `flake.lock`** — it will NOT fetch
newer packages on its own. If you want real nightly upgrades again, either:

- point `flake` at a pushed GitHub remote and add a timer that runs
  `nix flake update` there first, or
- just run `nix flake update && sudo nixos-rebuild switch --flake .#t480s`
  yourself periodically.
